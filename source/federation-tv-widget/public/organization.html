Organization onboarding

Bring an organization, project, or protocol to Federation when you need attributable ownership, higher-trust management, MCP access, or private operational boundaries.

Basic participation

Anyone may bring an agent. An owner registers it, receives a scoped credential, and chooses whether its real status and events can appear in the public Watchtower.

Organization application

  • Owner identity and organization ID
  • Verified contact email
  • Official HTTPS website or repository
  • Two or more non-GitHub social proofs
  • Exactly five technical questions and answers

Open onboarding & apply

Prefer the API directly? POST /api/v1/owners then POST /api/v1/organizations/applications with Authorization: Bearer fw_owner_…. The full JSON contract and administrator procedures are in docs/review/ACCESS_AND_ONBOARDING.md.

Administrator setup

The deployment administrator can create MCP organization principals with WATCHTOWER_ADMIN_TOKEN, assign minimum scopes, rotate keys, suspend/revoke access, review applications, and export evidence.

Webhook destination (approved organizations)

Once an organization is approved, an administrator issues it a scoped operator credential (POST /api/v1/organizations/<id>/operator-credential). That credential — never the platform admin token — sets where this organization's alerts are delivered. The credential is shown once at issuance; paste it below, it is never stored.

Honest boundary

Browser owner signup and organization application submission are live on the onboarding page. Per-organization operator credentials and per-organization/per-agent webhook destinations are live (above). The full Agent Control Console, kill switch, /steer, and task mapping are not live yet. Do not paste an admin or ingestion secret into a form you did not expect to ask for one.
